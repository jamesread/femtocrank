Introduction

This is a very simple theme of James Read's personal preferences, which tries to be bright and simple.

The examples below show the component and style choices in context.

Why?

  • Simple, semantic modern CSS in a small footprint
  • Avoid extraneous styles
  • High accessibility
  • Zero build or runtime dependencies
  • No JavaScript

Karma elements - inline

Annotations and tags share chip sizing and borders. Annotations are key/value pairs; add a karma type class (.annotation.note, …) for a --karma-*-tint value. Tags use the same tint fills (.tag.note, …).

fyi This is an annotation. scheduled next release status active

Neutral tag info note good/success warning severe bad/critical

Karma elements - Block (Notifications)

Notifications use a .notification-key filled with --karma-*-tint and body text in the normal text color. Inline links use the standard link style; add clickable when the whole notification is interactive.

INFO: New version available — click to view release notes.
NOTE: See the release notes for what changed.
SUCCESS: This is a success message.
WARNING: Disk usage is high — manage storage before continuing.
SEVERE: Service is degraded. Check the status page for updates.
CRITICAL: Database unreachable — follow the recovery runbook immediately.
